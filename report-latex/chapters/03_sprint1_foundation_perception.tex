\section{Introduction}
Sprint 1 built the perception pipeline that turns video frames into queue-relevant events. The main outcome was a reliable chain from capture to detection, tracking, and zone filtering inside the frame loop.

\section{Sprint Backlog}
The committed Sprint 1 backlog focused on the minimum viable perception chain:
\begin{itemize}
    \item Integrate YOLO-based person detection with configurable model size and inference device.
    \item Integrate persistent tracking so each detected person keeps a stable ID across frames.
    \item Define queue zones as polygons and count only detections inside these zones.
    \item Build a real-time loop that connects capture, detection, tracking, zone filtering, and rendering.
    \item Expose runtime controls through CLI options for source type, model parameters, and processing stride.
\end{itemize}

The use case follows a manager configuring a source and queue zone, then letting the runtime turn each frame into queue state updates. That sequence becomes the base for the analytics and automation layers that follow.

\subsection{Use Case Scenarios}
Three key scenarios are implemented in Sprint 1:
\begin{enumerate}
    \item \textbf{Person entry into queue zone:} a new tracker ID appears inside the polygon and is treated as a queue arrival candidate.
    \item \textbf{Tracker continuity across frames:} the same person is followed through consecutive frames using ByteTrack, reducing duplicate counting.
    \item \textbf{Zone filtering under mixed scenes:} detections outside the polygon are ignored for queue metrics, preventing unrelated people from polluting queue state.
\end{enumerate}

\section{Implementation}
\subsection{Detection Layer}
The detection layer is built around the \texttt{PersonDetector} class. It wraps Ultralytics YOLO inference and filters results to person class only (COCO class ID 0). The detector resolves device selection (\texttt{auto}/\texttt{cpu}/\texttt{cuda}/\texttt{mps}) and supports configurable image size for throughput control \cite{ultralytics_docs}.

\subsection{Tracking Layer}
The tracking layer uses \texttt{supervision.ByteTrack}. The tracker propagates persistent \texttt{tracker\_id} values across frames, which is essential for counting arrivals and departures rather than raw per-frame detections \cite{bytetrack2022}.

\subsection{Zone-Aware Filtering}
Zone logic is handled by the zone-management module. It accepts polygons in normalized or pixel coordinates, auto-scales normalized points to frame size, and evaluates inclusion using \texttt{PolygonZone} with bottom-center anchors for robust queue-ground contact checks.

\subsection{Main Loop Integration}
The pipeline integration is handled in the runtime orchestration layer. The runtime supports:
\begin{itemize}
    \item Source abstraction via \texttt{open\_video\_source()} for file/webcam/RTSP.
    \item Process stride control through \texttt{--process-every-n-frames}.
    \item Real-time overlay rendering (detections, IDs, zone, and metrics).
    \item Headless mode and dashboard event emission hooks for future API/runtime integration.
\end{itemize}

The sprint left behind a stable perception baseline that later sprints could build on for queue analytics and automation integration \cite{opencv_docs}.

\section{Conclusion}
Sprint 1 delivered the operational perception core: reliable person detection, persistent IDs, and queue-zone filtering. That baseline gave Sprint 2 stable event data to turn into rates and wait-time estimates.
